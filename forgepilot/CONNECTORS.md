# 工业连接器工厂

入口：[数据源与字段映射](http://127.0.0.1:18081/datasource)。在原工作台基础上增加工业连接器配置，原 JDBC 扫描和映射生命周期仍在第三个标签页。

## 初始化基础

- 来源：`forgepilot/catalog.json`，版本 `forgepilot-industrial-0.1.0`。`python3 forgepilot/build_connectors.py` 从现有本体生成 `industrial/connectors.json`，保留目录 SHA-256。
- 11 个模板：ForgePilot 演示、主数据工程、需求计划、采购协同、到货仓储、质量放行、生产追溯、物流交付、财务对账、售后处置、模型治理。
- 演示模板对应 18 类现有适配定义，共 126 条准确源集合/字段路径。
- 其余 10 个业务域模板覆盖 45 类对象、287 个目标属性。生产源表和字段未取得字典，因此保持待确认。其与演示模板可能指向相同本体目标，413 是多来源映射契约总数，不是新增 413 个本体属性。
- V3 新增 `fp_connector_config`、`fp_connector_log`；不修改已应用的 V1/V2，不复制库存，不写入 `bm_datasource` 或运行时生效映射 `bm_mapping`。
- Flyway 后自动 `INSERT IGNORE` 补齐缺失模板；页面再次初始化也只补缺失连接器，不覆盖已维护的名称、配置、映射或版本。已有草稿不会因重新生成模板而自动覆盖。

## 维护方式

1. 选择预置数据源，或在模板页以唯一编码创建一个新草稿。
2. 确认协议、真实端点、来源命名空间、负责人、权限、快照/水位策略、游标、分页、重试、重叠窗口、撤回与对账要求。
3. 凭据只接受 `env:变量名` 或 `vault:路径` 引用，本次不解析引用。禁止内嵌密码或令牌；HTTP 地址禁止 userinfo、查询参数和 fragment。
4. 在字段映射页按对象筛选，填写准确的源集合与精确字段键名，核对源类型与源单位。当前只支持直接映射，不执行表达式或单位换算。目标类型/单位取初始化基线；身份与必填字段必须纳入。
5. 保存配置与全部字段映射为同一版本。旧版本并发写入会拒绝；保存后旧校验结果失效。
6. 校验已保存配置。检查必需配置、源路径、当前未废弃概念/属性、当前模型属性大类、基线类型及单位。演示路径还必须与已实现适配器定义一致。
7. 可提交所选对象的 1–100 条 JSON 源记录样本，检查字段存在性、类型、必填与样本内身份重复。样本只在请求内处理；审计存结果与问题位置，不存原始样本或字段值。`EvidenceVersion` 的样本还需携带 `_evidence_id`，与版本号组成身份。
8. 导出配置或查看最近 30 条版本变更与校验记录。ADMIN/EDITOR 可维护，VIEWER/REVIEWER 只能查看。

## 运行边界

HTTP API、MySQL、JSON 是接入**契约**协议选项。工厂不发起远端连接、不解析密钥、不运行采集计划、不发布映射、不调度 Agent、不发送链上交易；`contractValidated` 只代表所列配置检查通过，`runtimeEnabled` 与 `liveConnectionTested` 均为 false。已有 MySQL 的实际连接与扫描沿用原 JDBC 服务，两个配置集合不自动互相生效。

生产接入还需真实源字典/接口文档、只读账号与范围、权限裁剪、首次全量及增量/迟到/撤回验证、重试隔离、鲜度与对账验收。不可把签署承诺或证书覆盖量当作合格实物库存，未知值不补零。正式模型发布与映射发布仍需独立审批。

## 验证

- `ConnectorFactoryServiceTest`：8 项，覆盖模板与未知来源、凭据拒绝、只读约束、参数边界、目标缺失、单位/路径漂移、必填身份和严格类型。
- 本地 API 验证：重复初始化不覆盖、乐观版本冲突、保存使校验失效、权限401/403、单位错误拒绝、演示批次真实只读快照样本通过、重复身份与布尔数量拒绝、原 JDBC 数量不变、业务快照内容与修订号不变。
- 本机运行记录保存在忽略的 `forgepilot/verification/`；PR验证摘要见 `PR_VALIDATION.md`，不提交密钥、数据库备份或原始样本。
